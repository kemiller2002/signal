# Architecture review

Work item: WI-0100 · Authority: `.sde/architecture/FOUR-TIER-ARCHITECTURE.md` (SDE-DOCTRINE-003 0.2.1, installed by Ordo 1.7.0). Ordo 1.20.0 ships the same `.sde` method bundle (0.2), so the doctrine is current.

## Verdict

**The four-tier F# architecture holds, and is now enforced mechanically.** Two structural findings remain open, and neither is a correctness defect.

## Tier mapping

| Tier | Doctrine | Signal | Evidence |
|---|---|---|---|
| 1 Semantic model | what can be true; no I/O, no frameworks | `Echelon.Signal.Engine` (types), `Echelon.Signal.Admin` (types) | Engine references only FSharp.Core and deterministic runtime assemblies |
| 2 Transition | legal change; requests effects as data | Engine (`Session`, `Rules`, `Submission`, `Import`), Admin (`AdminApp`, `GroupLifecycle`, `Credential`, `Intake`) | `AdminApp` returns effects as data; `Application/AdminWork` performs them |
| 3 Orchestration | coordinates use cases and effects; never a second authority | `Echelon.Signal.Application` (`Runtime`, `AdminWork`, `Bridge`, `*Store`, `*Wire`) | Limen protocol and Aegis boundary (`Boundary.fs`) |
| 4 Host | network, browser, clock, entropy, WASM | Application's adapters (Arca.GitHub, Fides.Client), `Echelon.Signal.Browser` (C# shim), `web-kernel/host.js` | Entropy enters only at the edge (HANDOFF, ARX-004) |

Dependencies point downward only: Browser → Application → Admin → Engine. The Engine has no project or package references.

## Enforcement added by WI-0100

`tests/Echelon.Signal.Tests/ArchitectureTests.fs` checks the rules on every build, so a violation fails CI before any code runs. Six tests pass:

1. The Engine assembly references nothing outside FSharp.Core and the deterministic runtime.
2. The Admin assembly may add only Engine, `Arca.Core` and `Limen.Routing`. It may never reference Fides, Aegis, Arca.GitHub, the Application or a network assembly.
3. Engine and Admin sources read no ambient effect: network, file system, clock, entropy, console, JS interop or environment.
4. That scan is shown to catch a planted clock read, so it cannot pass vacuously.
5. Every `[JSExport]` method in the C# shim forwards to `Echelon.Signal.Application.Runtime.dispatch*` and decides nothing. The project holds exactly one `.cs` file.

These are compile-artifact and source checks, the cheapest form of "eliminate invalid decisions before execution". They complement, not replace, Limen's strict verification (`limen verify --strict`), which already gates the kernel boundary.

## F# mandate and the C# exception

`Echelon.Signal.Browser` is C# because `[JSExport]` marshalling is generated by a C# source generator, and F# has no source generators. The project is a three-method forwarding shim with no state and no decision. Test 5 enforces that. **This is a justified technical exception.** It is recorded here and enforced by test, but it has not yet been approved by the owner as a formal exception (owner, rationale, revisit trigger), which SIGNAL-QUAL-001 requires. Revisit if Limen ships an F#-native export path.
