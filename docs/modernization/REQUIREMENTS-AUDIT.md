## Method

1. **Claims.** The implementers' gap analysis gives each group `tested`, `partial`, `missing` or `n/a`. A `tested` row must name a test.
2. **Traceability check (mechanical).** All 101 named tests cited by `tested` rows exist in source and **passed** in the 2026-11-08 baseline run (627/627).
3. **Independent verification.** Four verifier agents, none of which wrote the code, checked the 100 rows claimed `tested` that name a test or have a dedicated row. Each verifier read the normative source text, the implementation and the test, and was told to challenge the claim. Results: **76 VERIFIED, 24 PARTIAL, 0 NOT_VERIFIED, 0 UNDETERMINABLE** ([`evidence/independent-verification.json`](evidence/independent-verification.json)).
4. **Correction of the record.** The 24 PARTIAL groups were moved from `tested` to `partial` in `implementation-gap-analysis.md`. Each correction carries a dated WI-0100 note that names the gap, and the original evidence text is kept unchanged. Summary counts were recomputed (`GapAnalysisTests` passes), and the remediation is captured as **WI-0101** (high priority), which names all 24 groups.

The ledger now stands at: tested 74, partial 90, missing 18, n/a 1. Before WI-0100 the rows held 98 / 66 / 18 / 1, while the stated total read 97 / 67. Nothing tested the total row, so it had drifted. WI-0100 adds `GapAnalysisTests: the ledger totals are the counts of the status rows`, which fails on the old file.
